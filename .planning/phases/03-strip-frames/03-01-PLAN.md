<objective>
把"一张真条带 → N 帧"落成一个 bridge op，实现方式是对既有导出的**薄组合**：`fitPanelGrid` 定网格 → 每格二值抠底（新增的 `binary` 档）→ `removeFrameBorder` 去边 → `isolatePrimarySpriteComponent` 抢救邻格伸过来的残肢 → trim 到 alpha 包围盒 → 等比缩到 `cell × 0.875` 并用最近邻贴进固定 cell 居中。**基线对齐显式关闭**（D-27），**不用 `normalizeSpriteFrameScale`**（D-24），每个 best-effort 步骤都返回计数器，`gutter` 与拟合值都进 `meta`。

Purpose: POST-01 / POST-02 / GEOM-02。Phase 1 把两件事测清楚了：这张 8 格条带的拟合**不是** `W/N`（pitch 255 对均匀 256，phase 253），而 **gutter_ok 是 false**——8 条切线里恰好 1 条（fixture x=1528、原图 x=2180）在**源图剖面**上被占。D-22 的裁决是"先抢救，抢不回来才失败"。本计划把这个裁决落成可执行的判定，并且**用实测把两种被占分开**——这是本阶段最重要的一件事：

- **fixture 那条占线是模型涂的一层洋红水洗**（cast 153..174，整列 246 px）。二值抠底（阈值 128）把它整列抠掉，于是**同一条 strip 从 `gutterOk:false` 走向 8 帧产出**。
- **原图那条占线是生物自己的像素**（x=2180，58 px，cast 低到 0）。抠底抠不掉；`isolatePrimarySpriteComponent` 也救不回来，因为那 58 px 属于该格自己的主连通块，不是邻格伸过来的残肢。于是 `ok:false`、零帧、`gutter.unrescued:[2180]`——spec §8 要的"保留 raw，不产出错帧"。

同一条代码、两种结论，这正是 `gutter` 闸门要拦的东西。

Output: `app/lib/animFrames.ts`（唯一的那条链 + `fitBox` 纯算术）、`CHROMA_PRESETS.binary` 这一行、`BROWSER_IMPORTS` 的两个入口、`bridge.mjs` 的 `case 'strip-frames'`，以及让 `ie chroma --preset binary` 与新档同批可达的两处枚举。
</objective>

    **导出：**

    ```
    <!-- planner-discipline-allow: FRAME_FILL = 0.875 -->
    export const FRAME_FILL = 0.875
    export function frameMarginFloor(cell: number): number      // floor(cell * (1 - FRAME_FILL) / 2)
    export function fitBox(box: { bw: number; bh: number }, cell: number): { scale; w; h; x; y }
    export type StripFramesOptions = {
      dirs: readonly string[]          // 顺序即输出顺序，必填、非空

      key?: Partial<ChromaKeyOptions>  // 覆盖预设；不传就用 CHROMA_PRESETS[preset]
      fill?: number                    // 默认 FRAME_FILL
      border?: { coverage?: number; bandFraction?: number; alphaThreshold?: number }
    ```

    `fitBox(box, cell)`——**纯算术，不碰 canvas**，所以它能在任何环境里被断言：
    `cap = Math.floor(cell * fill)`；`scale = Math.min(1, cap / Math.max(bw, bh))`（**永不放大**——放大就是插值，D-24 要的是保真）；`w = Math.max(1, Math.round(bw * scale))`、`h = Math.max(1, Math.round(bh * scale))`；`x = Math.round((cell - w) / 2)`、`y = Math.round((cell - h) / 2)`。
    docblock 写明 87.5% 的出处：消费端把 64 px 的 cell 里放 56 px 的内容（`~/repos/dark-black/tools/build_handpainted_sheets.py:29`，`CELL 64 / INNER 56`，`56/64 = 0.875`）。`frameMarginFloor` 就是这条比例给出的留边下界（`cell/16`；`cell 512 → 32`、`cell 256 → 16`），它是**构造保证**，而实测值只会更好（512 上最小 131）。入参守卫：`cell` 非正整数、`bw`/`bh` 非正数、`fill` 不在 `(0, 1]` 各自抛错。

    `planStripFrames(stripDataUrl, opts)` 的步骤（**顺序即语义，不要重排**）：

    1. **解码一次**：`load(stripDataUrl)`，画进 `img.width × img.height` 的 canvas，`getImageData` 拿 RGBA 缓冲。后面所有量都从这一份缓冲来。
    2. **取样场色**：`fieldRgb = sampleFieldRgb(buf, w, h)`，`fieldHex` 自己格式化（`#RRGGBB` 大写），`fieldCast = magentaCast(fieldRgb)`。**不要**假设洋红，也不要写死 `#FF00FF`——实测两张真图的场色是 `#FD05FA`（cast 245）与 `#FC06FA`（cast 244）。
    3. **拟合**：`fit = fitPanelGrid(columnProfile(buf, w, h, fieldRgb), { cells, ...opts.fit })`。
    4. **归一化原点**（这一步不写就会**静默丢掉一整格**）：`fit.phase` 是模代表元。取
       `origin = phase - spacing * Math.max(0, Math.ceil((phase + cells * spacing - w) / spacing))`，
       然后 `bounds[j] = clamp(round(origin + j * spacing), 0, w)`（`j = 0..cells`）；`windows[j] = [bounds[j], bounds[j+1])`。docblock 写清楚：本 fixture 上 `phase 253` / `spacing 255` 让朴素原点在末格越界 8 px，归一化后是 `origin -2`、窗口 `[0,253) … [1783,2038)`、左余 2 px 右余 10 px；原图（2928 宽）是 `origin 20`、窗口 `[20,380) … [2540,2900)`。**留白允许，丢格不允许。** `x1 - x0 < 2` 的窗记 `empty` 并跳过。
    5. **逐格切**：`sliceImageGrid` 会把整张图缩放到 `cols × cellSize`（隐式缩放），**不能用**。手工 `drawImage(img, x0, 0, w, h, 0, 0, w, h)` 每格一张 data URL，`imageSmoothingEnabled = false`（切格是 1:1 搬运）。
    6. **每格：key → border → isolate**，三步都 best-effort、都计数：
       - `chromaKeyToAlpha(cellUrl, { ...resolvePreset(presetName), ...opts.key })`，`preset` 默认 `'binary'`。计数 `keyed++`。
         **查表不能裸写 `CHROMA_PRESETS[presetName]`**：`CHROMA_PRESETS` 是 `as const`，用 `string` 下标报 `TS7053`（实测），而本计划要求 `tsc --noEmit` 绿——执行者多半会随手加 `as any` 或 `?? CHROMA_PRESETS.default` 绕过，那正好把"未知预设名"变成一个**静默退回纯洋红键色**（`chromaKeyToAlpha` 的 `keyR/G/B` 默认 255/0/255）的入口。写一个显式守卫，未知名字**抛**：
         ```ts
         function resolvePreset(name: string): ChromaPreset {
           const p = (CHROMA_PRESETS as Record<string, ChromaPreset | undefined>)[name]
           if (!p) throw new Error(`unknown chroma preset: ${name}`)
           return p
         }
         ```
         于是 `planStripFrames(url, { dirs, preset: 'nope' })` 不会安静地画一张全洋红。**两条路径要分清**：闸门自己 `import` 进程内调用时，`runJobs` 只有 `try/finally`、**不捕** `PAGE_PROGRAM` 的异常，所以是**直接 reject**；只有 `invokedDirectly` 的子进程分支才会把异常包装成 `{ok:false, error}` 信封。断言一律用 `assert.rejects`，别去断信封。现有的 `if (!preset) throw ...` 那一行保留，两处都指向同一个判定。
       - **`fieldSurvived`**（见下面第 8 步为什么必需）：抠底之后取该格四个角的 alpha，**四个都 > 0** 就 `fieldSurvived++`。含义：这一格的角落还被场色占着，说明这一抠底什么都没抠掉。
       - `removeFrameBorder(keyed, opts.border)` 包在 try/catch 里；**返回值 !== 入参** 才计数 `borderTrimmed++`（`imageProcessor.ts:2849` 的 `if (!changed) return cellDataUrl` 保证这个比较是充要的——"跑过但什么都没干"和"真的清了边"分得开）。catch 时保留未去边的版本并 `borderFailed++`。
       - `isolatePrimarySpriteComponent(bordered)` 包在 try/catch 里；**返回值 !== 入参** 才计数 `isolated++`。catch 时保留上一版并 `isolateFailed++`。
       - `isolatePrimarySpriteComponent` 不返回诊断，`isolatedPx` 自己算：隔离前后各取一次 alpha 缓冲，数"隔离前 > 0 且隔离后 === 0"的像素。
    7. **gutter 闸门第一级——抢救后的占据度**（D-22 的核心）：对每条**内部**切线 `x = round(phase + k * spacing)`（`k = 1..cells-1`，`0 < x < w`），占据度 = `max(左格末列的不透明像素数, 右格首列的不透明像素数)`；**不透明 = `alpha > 0`**。（这与 Phase 1/2 的剖面是两个量：剖面数的是"与场色的距离 > 60"，那是**源图**上的量；这里数的是抠底之后的 alpha。`fitted.cutLines[].mass` 与 `gutter.lines[].keyed/after` 因此是**四个不同的字段**，别混。）
       `tolerance = Math.max(1, Math.round(fit.medianMass * (opts.fit?.gutterRatio ?? GUTTER_RATIO)))`（本 fixture 上 167 × 0.02 → **3**，原图 239 × 0.02 → **5**）。
       `lines[k] = { x, keyed, after }`：`keyed` 在步骤 6 的抠底之后、去边之前量；`after` 在隔离之后量（**这是闸门实际判的那个数**）。`rescued` = 由"被占"变干净的条数；`unrescued` = 仍然被占的 x 数组；`gutter.ok = unrescued.length === 0`。
       **`fit.gutterOk`（源图剖面的自信度）与 `gutter.ok`（抢救后的判定）是两个字段，都要进 `meta`。** 前者是 provenance，后者是 pass/fail。本 fixture 上两者**恰好相反**（`gutterOk:false` 而 `gutter.ok:true`），这正是要让人看见的那件事。
    8. **gutter 闸门第二级——`fieldSurvived`**（**没有这一级，闸门是假的**）：第一级有一个实测过的洞——`castThreshold` 设到 256 时抠底一个像素都不抠，整格是实心洋红，但 `removeFrameBorder` 的 `colOpaque >= colNeed` 恰好把**被采样的那几列边缘**整列清零，于是"切线两侧 0 个不透明像素"成立、`rescued` 记成 7、闸门放行一整条**实心洋红**（实测：8/8 格如此，`meta.ok` 必须由 `fieldSurvived` 拦住）。所以：
       `ok = gutter.ok && counters.fieldSurvived === 0 && counters.empty === 0`。
       三层各拦一类：`gutter.ok` 拦"切到了生物像素"（GEOM-02），`fieldSurvived` 拦"抠底根本没生效"（预设被改坏 / 场色变了 / 阈值被覆盖错），`empty` 拦"某格什么都切不出来"。
    9. **trim + 套格**：每格最终的 alpha 做包围盒（`alpha > 32`），`fitBox(bbox, cell)` 定 `scale/w/h/x/y`，再把该格 `drawImage(cellCanvas, minX, minY, bw, bh, x, y, w, h)` 到一张 `cell × cell` 的**全新透明** canvas 上，`imageSmoothingEnabled = false`（**最近邻**，D-24）。计数 `scaled += scale < 1 ? 1 : 0`、`centred++`。包围盒为空 → 该帧不产出，`empty++`。
       **不要**做 trim→fit 之外的任何变形：不旋转、不按中线翻转、不把底边对齐到任何 target（那就是 D-27 禁掉的那件事）。
    10. **判定**：`ok` 由第 8 步给出。`ok === false` 时 **`frames` 返回空数组**——spec §8 要的是"保留 raw，不产出错帧"，半套帧比没有帧更坏。`meta` 照常完整返回（含 `fitted`/`gutter`/`counters`），让 CLI 能报出**为什么**失败。
